## 테스트 범위와 개발 아키텍처

| 단계 | 도구 | 대상 |
|---|---|---|
| 백엔드 단위·API·DB 통합 | pytest | 도메인 규칙, 라우터 계약, 게이트웨이, 수집·적재(테스트 전용 DB) |
| 프론트엔드 단위·컴포넌트 | Vitest · Testing Library, `tsc` 타입 검사 | 화면 컴포넌트, 상태·계산 보조 함수, mock API 픽스처 |
| 사용자 시나리오(E2E) | Playwright headless 스크립트 `frontend/tests/*.cjs` | 깔때기 전체 흐름, AI 리포트, 첫 화면 반응형 |
| 실서버 스모크 | 실행 중인 백엔드에 직접 요청 | 의도 해석, 금리, 입력 오류, AI 리포트 실호출 |

대상 구조는 [상위 설계]({{ '/docs/architecture/' | relative_url }})를 따릅니다. 아래 결과는 모두 **로컬 개발 환경**에서 얻었습니다. 배포 환경 테스트, 부하·동시 요청 테스트는 아직 하지 않았습니다.

## 사전 준비사항

- Docker로 데이터 스토어 실행(PostgreSQL·Redis·Neo4j)
- 백엔드: pytest가 테스트 전용 DB(`localhostdaegu_test`)를 자동으로 만들고 마이그레이션·마스터 시드를 실행합니다. DB 이름이 `_test`로 끝나지 않으면 중단해 개발 DB를 보호합니다.
- 실데이터 E2E·스모크: 공공데이터를 적재한 개발 DB, 실행 중인 백엔드(8300)·프론트엔드(3300), AI 리포트는 Gemini 키가 필요합니다.
- E2E는 브라우저 창을 띄우지 않는 headless로 실행하고, 실행 중인 서버를 재사용하는 옵션(`E2E_REUSE_SERVER=1`, `E2E_API_BASE`)을 씁니다.

**재현 제한:** 일부 백엔드 테스트는 저장소에 올리지 않은 원본 데이터 파일(`data/raw`)이 있어야 통과합니다. 새로 받은 저장소나 CI에서는 그대로 재현할 수 없습니다.

## 성능 측정 계획

TPS는 **API 요청 처리량(req/s), 거래 처리량(tx/s), 모델 토큰 생성 속도(token/s)**를 구분합니다. 블록체인 거래가 없으므로 거래 처리량은 해당 없음입니다. 아래는 단건 실측이며 목표값은 아직 정하지 않았습니다.

| 측정 구간 | 지표 | 조건 | 결과 |
|---|---|---|---|
| AI 리포트 전체 스트림 | 소요 시간 | 로컬, 실 Gemini, 대신동·카페 1건 | 10.4초(9/17 1차) · 12.3초(2차) · 13.4초(9/18 E2E) |
| 인허가 전량 수집 | 소요 시간 | 7업종 × 8개 구·군 | 약 18분, 161,115건(9/16) |
| 검색 색인 증분 | 소요 시간 | 뉴스 1,595건, 유료 키 | 69.3초(9/17) |
| 전체 요청 | 처리량·p50/p95 응답시간·실패율 | 동시 사용자·지속 시간 | **미측정** |
| 로컬 LLM 추론 | 토큰 생성 속도 | 후보당 28프롬프트, Ollama eval | gemma4 48 · kanana 81 · exaone 85 token/s(9/18). 서비스 전체 처리량과는 별도 |
| 모델별 생성 | 첫 조각·총 시간 p50 | 같은 컨텍스트·프롬프트 | Gemini 1.68/2.12초, gemma4 0.46/2.95초. 전체 리포트가 아닌 개별 프롬프트 기준 |

p95 응답시간은 요청 100건 중 약 95건이 그 시간 안에 끝났다는 뜻입니다. 목표값은 측정 전에 합의하고, 실측값과 구분합니다.

## 결과 기록 형식

테스트 ID / 실행일 / 코드 버전 / 데이터 / 환경 / 설정 / 절차 / 기대 결과 / 실제 결과 / 판정 / 로그 / 결함 / 재검증 결과를 기록합니다. 실행 원문과 스모크 출력은 서비스 저장소의 개발 기록과 작업 폴더에 남기고, 이 페이지에는 판정과 핵심 수치만 옮깁니다.

배포 후 같은 시나리오를 배포 주소에서 다시 실행한 결과는 [최종 검수]({{ '/docs/acceptance/' | relative_url }})에 남깁니다.
