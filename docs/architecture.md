## 개발 개요

9월 18일 작업 로그의 사전상담 전환·후속 저장 배선·모델 평가까지 반영한 구조입니다. 이전 자작 서비스 Metabole(서울 상권)을 대구 기준으로 바꿨고([DEC-006]({{ '/decisions/' | relative_url }})), 한 문장 질문 → 지도 선택 → 자금 계산·비교·선택 → 상담자료 → 공식 안내 흐름을 실백엔드로 완주했습니다. **배포는 아직 하지 않았습니다.**

## 모듈 중심 Data Flow

<div class="diagram-frame"><img src="{{ '/assets/images/architecture.svg' | relative_url }}" alt="예비 창업자의 질문과 자금계획을 Next.js와 FastAPI가 처리해 계산안 비교와 상담자료로 연결합니다. 상품·상담 기록은 PostgreSQL에 저장하고, Gemini가 해석하며 로컬 대체 모델은 평가를 마친 상태입니다."><p class="diagram-caption">2026-09-18 사전상담 후속 작업 기준 · 로컬 구성. 색상은 기능 묶음, 화살표는 요청·조회·적재 방향입니다.</p></div>

1. 사용자가 채팅 첫 화면에 한 문장을 입력하면 백엔드가 구·동·랜드마크, 업종, 예산을 추출합니다.
2. 지도 화면이 해당 행정동을 보여 주고, 행정동 × 업종 지표와 위험도를 조회합니다.
3. 비용·자기자본·예상 매출로 총 준비자금·조달 필요액·희망대출 반영 후 부족액을 계산하고, 최초안과 현재안을 비교·선택합니다. 상담 후보는 iM뱅크 연결 근거와 자격·자치구 조건으로 고릅니다.
4. 상담자료 요청 시 입력을 서버 엔진으로 다시 계산하고 계획·비교·계산표·정책자금·확인 질문·상권 섹션을 SSE로 전달합니다. 수치·비교표·미확인 항목은 코드가 정하고 Gemini가 설명·질문을 씁니다. 선택 연도는 지표와 위험도까지 전달합니다.
5. 화면 초안은 sessionStorage에 보관하고, 상담자료 생성 시 서버에 세션·계획·노트를 기록합니다. 재생성은 같은 세션을 갱신하며 완성된 자료 다운로드 시 선택안과 sha256 해시를 기록합니다. 공식 안내 이동은 은행에 자료를 전송하지 않습니다.
6. 정기 수집 작업이 공공 데이터를 매일·매시 적재하고, 지표 재계산과 검색 색인을 갱신합니다.

## 모듈과 필수 조건

백엔드는 헥사고날 구조(도메인 · 유스케이스·포트 · 어댑터 · 조립)이며, 기능마다 bounded context를 둡니다.

| 기능 묶음 | 백엔드 모듈 | 프론트엔드 | 입력 → 출력 | 필수 조건 |
|---|---|---|---|---|
| 입력 해석 | `intent` | `intent-gate`(채팅 첫 화면) | 한 문장 → 구·동 코드, 업종, 예산 | 긴 지명을 먼저 비교("달서구"를 "서구"로 오인하지 않음), 단위가 붙은 금액 합산 |
| 상권 진단 | `master`(구·동·업종·경계), `store`(인허가), `metric`(지표·위험도) | `map-explorer`(지도·사이드 패널·위험도 카드) | 행정동·업종·연도 → 점포 수·폐업률·성장률, 위험도 | 기본 연도는 마지막 완결 연도. 위험도는 상대 순위이며 실패 확률로 표시하지 않음 |
| 자금 계산·매칭 | `finance`(재무 엔진), `matching`(후보), `product`(상품 DB), `shock`(금리) | `simulator`(계산안 비교·선택·후보 카드) | 비용·자금·지역 → 자금 구성·시나리오·상담 후보 | 계산은 코드. 재무 미입력 시 계산·매칭 생략. matching은 product 입력 포트 사용 |
| 상담 기록 | `consultation` | 상담 초안·자료 내보내기 | 세션·계획·가정·확인 질문·문서 해시 | 화면 정본은 sessionStorage, 서버 기록은 감사·재현용. 저장 실패가 자료 생성을 막지 않음 |
| 외부 데이터 준비 | `dataset`·`indicator` | 미연결 | 데이터셋 메타데이터·지역 지표용 스키마 | 센터 데이터 미확보로 두 테이블은 비어 있음 |
| AI 리포트 | `analysis`(목적별 구성·SSE), `rag`(검색), `news`·`funding`(근거 문서) | `agent-report`(진행·자료 뷰) | 지역·연도·재무·상담 입력 → review 또는 handoff | 수치·비교표는 코드, 설명·질문은 AI. handoff에 재무·상담 입력 필수 |
| 수집 | `store`·`funding`·`news`·`rent`·`shock`·`rag` 수집기, `scripts/*.sh` | — | 외부 API → DB·색인 | 소스별 오류 격리, 가장 나쁜 종료 코드 기록, 중복 실행 방지 |

서울 원본에서 넘어온 `convenience`(편의점)와 `tobacco`(담배소매업 파일 로더)는 코드만 있고 대구 데이터는 적재하지 않았습니다.

## AI 모델 학습·추론 흐름

### 학습·평가 준비 — 자체 학습 없음

모델을 직접 학습하거나 미세 조정하지 않습니다. 기본 경로는 외부 모델 API(Google Gemini)이고, 외부 API가 끊겼을 때를 위해 로컬 모델(Ollama) 경로를 같은 포트 뒤에 어댑터로 두었습니다.

| 용도 | 온라인(기본) | 오프라인(대체, 평가 완료·전환 전) | 비고 |
|---|---|---|---|
| 리포트 해석 문단 | `gemini-3.8-flash` | `gemma4:12b` (환경변수 `REPORT_WRITER_PROVIDER=ollama`) | 팀 결정 "최신 정식 Flash 모델"([DEC-009]({{ '/decisions/' | relative_url }})). 로컬 대체는 [DEC-022]({{ '/decisions/' | relative_url }}) |
| 검색 색인·질의 임베딩 | `gemini-embedding-001`(1536차원) | `qwen3-embedding:4b`(2560차원) | 색인과 질의는 같은 임베더만 짝지어 사용. 로컬 전환은 색인 컬럼을 2560차원으로 바꾸고 전량 재색인한 뒤 가능 |

9월 18일에 온라인·오프라인 후보를 같은 코퍼스(3,448건)·질문(80건)·프롬프트로 나란히 평가했습니다. 임베딩은 qwen@2560이 Top-1 0.762로 Gemini(0.700~0.738)와 동급 이상이었고, 리포트 생성은 gemma4:12b가 Gemini와 같은 게이트 전부 통과(1.000)를 냈습니다. 두 경로가 고르는 근거 문서는 절반가량 다릅니다. 상세는 [모델 평가]({{ '/docs/model-evaluation/' | relative_url }})에 있습니다. 평가셋 80건은 자동 생성한 미검수 상태이며, 문장의 설득력·해석 정확도는 아직 재지 않았습니다.

### 서비스 추론 — 구현

분석 요청 저장(한 번만 쓰는 ID) → 에이전트가 차례로 자료 수집: 상권(지표·위험도) → 관련 뉴스 검색(pgvector) → 자금(재무 입력이 있으면 재무 계산, 금융상품 매칭, 정책 공고 검색) → 섹션마다 코드가 제목·점수·표를 먼저 전송 → Gemini가 해석 문단을 스트림 → 참고 자료와 함께 완료 이벤트 전송.

- 에이전트 하나가 실패해도 오류 상태만 알리고 나머지를 계속 진행하며, 스트림은 항상 완료 이벤트로 끝납니다.

- 사용자 질문과 검색 문서는 태그로 감싸고, 그 안의 지시는 따르지 않도록 시스템 지시에 명시했습니다.
- 임베딩 호출은 호출 한도(429)·일시적 5xx 오류에 재시도합니다. 해석 문단 생성이 실패한 섹션은 대체 문구로 채웁니다.
- 분석 요청 저장소가 메모리에 있어 **백엔드는 워커 1개로 실행해야 합니다.** 워커를 늘리려면 Redis 같은 공유 저장소 어댑터가 필요합니다.

## 배포 구조 — 확정, 실행 전

배포 주소는 **localhostdaegu.cloud**이며 아직 배포하지 않았습니다. 프론트엔드는 Vercel, 백엔드는 로컬 GPU 머신에 Cloudflare Tunnel, DB는 로컬 Docker로 정했습니다([DEC-020]({{ '/decisions/' | relative_url }})). 절차는 서비스 저장소 `docs/deploy-vercel-cloudflare.md`에 있습니다. 도메인이 아직 가비아 네임서버라 Cloudflare로 옮기는 전파 시간이 필요합니다.

| 결정·확인 항목 | 현재 코드에서 확인한 조건 |
|---|---|
| AI 키 | 백엔드에 Gemini 키가 없으면 분석 시작 요청이 500. 리포트 모델은 환경변수로 바꿀 수 있고 코드 기본값은 `gemini-3.8-flash` |
| CORS | 로컬 출처는 항상 허용하고 `CORS_ALLOW_ORIGINS`(쉼표 구분)로 운영 도메인을 추가(9/18 반영) |
| 워커 수 | 분석 요청 저장소가 메모리라 워커 1개 |
| 프록시 | SSE 응답에 버퍼링 해제 헤더를 보내지만, 실제 프록시에서 스트림이 모이지 않는지 배포 후 확인 필요 |
| 정기 수집 | 운영 환경의 crontab·로그·키 관리 방식 결정 필요 |

## 요구사항별 구현 목표와 시나리오

REQ-002는 자금 구성·계산안 비교·지역별 상담 후보·자료 저장을, REQ-003은 선택 연도 전달과 목적별 리포트 구성을 확인합니다. [테스트 시나리오]({{ '/docs/testing/' | relative_url }})에 정상·예외 경로를 연결합니다. 기간 일치(①)와 자금 점검 동선·가정 표시(③)는 완료됐고, AI 진행 표시(②)와 데이터 신뢰 표시(④)는 보완 예정입니다. 코드 프리즈는 해제했습니다.
