## 개발 개요

세 기능 후보가 입력 검증·데이터 조회·AI 설명·출처 연결을 공유하는 구조를 검토합니다. 아래 흐름은 논의를 위한 개념 설계이며 실제 구현 구조로 확정하지 않았습니다.

## 모듈 중심 Data Flow

<div class="diagram-frame"><img src="{{ '/assets/images/architecture.svg' | relative_url }}" alt="사용자의 요청을 입력 검증 후 선택한 세무·매출, 창업 매칭, 상권 컨설팅 모듈로 전달하고, 자료 조회와 AI 설명을 거쳐 출처와 함께 결과를 반환하는 설계 검토안"><p class="diagram-caption">개념 설계 · 색상은 기능 모듈을 나타냅니다. 화살표에는 전달되는 데이터나 수행 단계를 표시합니다.</p></div>

1. 사용자가 질문과 필요한 조건·자료를 입력합니다.
2. 공통 입력 검증에서 필수 항목과 지원 범위를 확인합니다.
3. 선정된 기능 모듈이 필요한 자료를 조회하고 규칙 기반 처리 또는 분석을 수행합니다.
4. 필요한 경우 AI가 분석 결과와 조회 근거를 사용해 설명을 생성합니다.
5. 결과·출처·기준일·미확인 사항을 함께 보여줍니다.

## 모듈과 필수 조건

| 모듈 | 색상 | 입력 → 출력 | 필수 조건 제안 |
|---|---|---|---|
| M0 공통 입력·결과 | 회색 | 사용자 입력 → 검증된 요청 / 결과 화면 | 잘못된 입력과 처리 실패 구분 |
| M1 세무·매출 | 청록 | 매출·증빙 자료 → 요약·확인 항목 | 집계와 설명, 원본 근거 연결 |
| M2 창업 매칭 | 보라 | 창업 조건 → 후보 정보·매칭 이유 | 원문 조건과 정보 기준일 확인 |
| M3 상권 컨설팅 | 황토 | 지역·업종·질문 → 지표·해설 | 관측값과 해석 구분 |
| M4 데이터·AI 공통 | 남색 | 필요한 자료·근거 → 처리 결과·설명 | 접근 실패·근거 부족 처리 |

## AI 모델 학습·추론 흐름

### 학습·평가 준비 — 학습 여부 미정

데이터 출처 확인 → 샘플과 평가셋 구성 → 기준 성능 측정 → 추가 학습 필요성 판단 → 학습을 선택한 경우 학습·평가 → 모델 버전 기록.

외부 모델 API만 이용하는 경우에는 별도 학습을 하지 않는다고 명시합니다. 현재 모델·학습 방법·평가셋은 선정 전입니다.

### 서비스 추론 — 검토안

검증된 사용자 요청 → 관련 데이터·근거 조회 → 기능 모듈의 처리 결과 → AI 설명 생성 → 출처 연결·응답 검토 → 사용자에게 반환.

추론 실패 시에는 오류 원인을 설명하고 다시 시도할 수 있는 범위를 안내하는 방식을 검토합니다. 사용할 대체 모델이나 재시도 횟수는 미정입니다.

## 개발 환경과 기술 요소

| 구분 | 현재 확인한 내용 | 결정할 항목 |
|---|---|---|
| 문서 사이트 | Jekyll + Just the Docs | 문서·프로필·산출물 업데이트 |
| 서비스 프론트엔드 | 스택 미정 | 화면 구성·입력 방식 |
| 서비스 백엔드 | 제공된 초기 작업 기록에 Python 기반 준비 기록 존재 | 실제 코드 확인과 API 계약 |
| 데이터 저장소 | 초기 기록에 pgvector·Neo4j·Redis 구성 기록 존재 | 각 저장소의 필요성과 실제 사용 범위 |
| AI 모델·라이브러리 | 미정 | 모델 선택·라이선스·비용·실행 환경 |
| 인프라 | 배포 환경 미정 | 로컬·클라우드 구성과 이전 방안 |

서비스 저장소의 초기 준비 기록은 이 문서 사이트에 복사된 `jekyll.md`를 참고했습니다. 준비된 인프라와 실제로 동작하는 기능은 구분해 확인합니다.

## 외부 연동 계획

| 연동 후보 | 목적 | 현재 상태 | 확인할 항목 |
|---|---|---|---|
| 공공데이터·대구 지역 데이터 | 상권 분석 근거 | 미연동 | 데이터셋·지역 단위·갱신 주기·이용 조건 |
| 창업 지원 정보 | 후보 정보 탐색 | 출처 미선정 | 원문·조건·기준일·수집 방식 |
| AI 추론 서비스 | 근거 기반 설명 | 모델 미선정 | 요청 형식·비용·제한·실패 처리 |
| 금융·정산 관련 API | 매출·정산 연계 가능성 검토 | 이용 가능 여부 미확인 | 접근 권한·샘플·제공 범위 |

블록체인은 데이터 증빙 등 구체적인 적용 목적과 검증 방법이 정해진 경우 범위에 포함하는 안을 검토합니다. 현재 적용 여부는 미정입니다.

## 요구사항별 구현 목표와 시나리오

M1은 원자료와 요약의 일치, M2는 입력 조건과 정보의 적합성, M3는 지표와 출처의 일치를 확인합니다. 공통으로 입력 오류·외부 API 실패·데이터 부족을 [테스트 시나리오]({{ '/docs/testing/' | relative_url }})에 연결합니다.
