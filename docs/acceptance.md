## 개발 내용 Flow와 동작 과정

시작 → 설정 확인 → 입력 → 데이터 처리 → AI 추론 → 결과 확인 → 로그 확인 → 종료의 실제 경로입니다. 상세 동작은 [상세 설계]({{ '/docs/detailed-design/' | relative_url }})와 같습니다.

1. 데이터 스토어와 백엔드·프론트엔드를 실행하고 백엔드 상태 확인(`/health`).
2. 첫 화면에 한 문장 입력 → 지역·업종·예산 인식.
3. 지도에서 행정동 지표·위험도 확인(기본 2025년).
4. 시뮬레이션에서 비용·자금 입력 → 결론 화면의 부족 자금과 매칭 상품 확인.
5. AI 분석 실행 → 섹션별 리포트와 참고 자료 확인.
6. 수집 로그(`logs/*.log`)와 서버 로그에서 오류·키 흔적이 없는지 확인.

## 설치·소스 이전 매뉴얼

서비스 저장소 인수인계 문서에 적힌, 실제로 실행해 확인한 명령입니다.

```bash
docker compose up -d db redis neo4j                       # 데이터 스토어
cd backend && .venv/bin/python -m pytest tests/ -q        # 테스트 전용 DB 자동 생성
cd backend && .venv/bin/uvicorn main:app --port 8300      # 백엔드
cd frontend && npm run dev                                # 프론트엔드 :3300
cd frontend && npx vitest run                             # 프론트엔드 테스트
node frontend/tests/funnel.cjs                            # 깔때기 E2E(headless)
```

1. 소스 저장소를 받고 main의 검수 버전 확인
2. Python 가상환경·Node 의존성 설치
3. 루트 `.env` 또는 `backend/.env`에 외부 API 키 입력(값은 커밋하지 않음)
4. 데이터 스토어 실행, 마이그레이션·마스터 시드 적용
5. 수집기 실행으로 공공데이터 적재(인허가 전량 약 18분), 검색 색인 생성
6. 서비스 실행과 `/health` 확인
7. 핵심 시나리오 재현(E2E 스크립트)
8. crontab 등록, 로그 확인·재시작

**알려진 재현 제한:** 새로 받은 저장소에서는 일부 테스트가 저장소에 없는 원본 데이터 파일을 요구해 그대로 통과하지 않습니다. 새 환경에서 처음부터 설치해 재현하는 절차는 아직 검증하지 않았습니다.

이 Jekyll 문서 사이트의 실행 방법은 저장소 README에 따로 정리했습니다.

## 사용자 설정·예외 처리

| 사용자가 조정하는 값 | 범위·기본값 | 반영 시점 |
|---|---|---|
| 지도 기준 연도 | 2019~2026, 기본 2025. 2026은 "(집계 중)" | 즉시(지도 색상). 요약 카드·위험도·AI 분석은 선택과 관계없이 기본 연도 사용 — ①에서 보완 예정 |
| 재무 입력 13항목 | 금액 0 이상, 비율 0 이상 1 미만, 원가율 + 수수료율 < 1. 대출금리 기본값은 최신 중소기업 대출금리(실패 시 4.5%) | 시뮬레이션 실행 시 |
| AI 추가 질문 | 500자 이하 | 분석 시작 시 |

검수한 예외 동작(잘못된 입력 422, 없는 분석 요청 404, AI 실패 시 대체 문구)은 [TC-004]({{ '/docs/testing/' | relative_url }}#tc-004)에 정리했습니다.
